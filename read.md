# Ollama Monitor

**Универсальная система мониторинга Ollama с веб-интерфейсом, API-прокси, аналитикой производительности LLM и мониторингом GPU.**

Ollama Monitor предназначен для локального использования и помогает анализировать работу языковых моделей, оценивать скорость генерации, отслеживать запросы от различных приложений и контролировать использование аппаратных ресурсов.

Основной адрес веб-интерфейса:

`http://localhost:8881`

Прокси Ollama API:

`http://localhost:8881/api/`

OpenAI-совместимый API:

`http://localhost:8881/v1/`

Стандартный адрес Ollama:

`http://localhost:11434`

---

## 1. Основные возможности

### Мониторинг Ollama

- Проверка доступности сервера Ollama.
- Определение версии Ollama.
- Получение списка установленных моделей.
- Отслеживание моделей, загруженных в память.
- Мониторинг активных запросов.
- Отображение ошибок и состояния сервера.
- Сбор доступных сведений из логов Ollama.

### Мониторинг запросов

Для каждого запроса система собирает доступную информацию:

- Дата и время.
- Название модели.
- IP-адрес клиента.
- Название приложения, если оно известно.
- API endpoint.
- HTTP-статус.
- Продолжительность запроса.
- Время загрузки модели.
- Количество входных токенов.
- Количество выходных токенов.
- Скорость обработки контекста.
- Скорость генерации ответа.
- Время до первого байта.
- Ошибки и причины завершения запроса.

Набор доступных показателей зависит от API, через который выполняется запрос, и от статистики, возвращаемой Ollama.

Неизвестные показатели не должны подменяться приблизительными или фиктивными значениями.

### Мониторинг GPU

Поддерживается наблюдение за NVIDIA GPU.

Для каждой видеокарты отображаются доступные показатели:

- Название устройства.
- Индекс GPU.
- UUID.
- Общая видеопамять.
- Используемая видеопамять.
- Свободная видеопамять.
- Загрузка GPU.
- Температура.
- Энергопотребление.
- Частоты GPU и памяти, если доступны.

Предусмотрена поддержка систем с несколькими видеокартами.

Примеры возможных конфигураций:

- Tesla V100 16 GB.
- RTX A4000 16 GB.
- RTX 3090 24 GB.
- Несколько одинаковых GPU.
- Несколько GPU разных моделей.

Система должна корректно работать и без NVIDIA GPU, отключая недоступные функции мониторинга оборудования.

**Важно:** суммарный объём памяти нескольких видеокарт не означает, что любая модель автоматически может использовать всю эту память. Распределение модели зависит от Ollama, используемого backend и конфигурации оборудования.

### Аналитика производительности

Система позволяет анализировать:

- Среднюю скорость генерации каждой модели.
- Медианную скорость генерации.
- Скорость обработки входного контекста.
- Среднюю продолжительность запросов.
- Количество обработанных токенов.
- Количество ошибок.
- Изменение скорости при увеличении контекста.
- Зависимость производительности от модели и аппаратных ресурсов.

### История и статистика

Все доступные сведения о запросах сохраняются в локальной базе SQLite.

Предусмотрены:

- История запросов.
- Фильтрация по моделям.
- Фильтрация по клиентам.
- Фильтрация по IP-адресам.
- Поиск по времени.
- Экспорт CSV.
- Экспорт JSON.
- Графики производительности.
- Сравнение моделей.
- Анализ длительных запросов.

### Веб-интерфейс

Интерфейс предоставляет следующие разделы:

- Dashboard — общая статистика.
- Requests — история запросов.
- Models — статистика моделей.
- GPU — мониторинг видеокарт.
- Clients — информация о клиентах.
- Logs — журналы событий.
- Settings — настройки приложения.

Интерфейс должен обновляться без полной перезагрузки страницы.

Для передачи событий в реальном времени используется WebSocket.

## 2. Архитектура

Ollama Monitor состоит из нескольких основных компонентов.

### Backend

Python, FastAPI и Uvicorn обеспечивают работу HTTP API, веб-интерфейса и прокси.

### API Proxy

Прокси принимает запросы от клиентских приложений, передаёт их в Ollama и собирает статистику.

### Request Tracker

Компонент отслеживает жизненный цикл запросов, измеряет время выполнения и сохраняет результаты.

### GPU Monitor

Получает сведения о видеокартах через NVIDIA Management Library и, при необходимости, `nvidia-smi`.

### Ollama Monitor

Проверяет состояние сервера, получает информацию об установленных и загруженных моделях.

### Database

SQLite используется для локального хранения истории запросов, метрик и настроек.

### Web Interface

Веб-интерфейс предоставляет таблицы, графики, фильтры и отображение текущего состояния системы.

## 3. Режимы работы

### Passive Monitoring

Пассивный режим позволяет наблюдать за Ollama без перенастройки клиентских приложений.

Используются доступные API, системные показатели и журналы.

В этом режиме можно получать сведения о моделях, состоянии сервера и загрузке оборудования.

Однако пассивный режим не гарантирует получения полной статистики каждого запроса. В частности, информация о количестве токенов и скорости генерации может отсутствовать.

### Proxy Monitoring

Режим прокси предназначен для подробного мониторинга запросов.

Клиентские приложения обращаются к Ollama Monitor, который пересылает запросы на исходный сервер Ollama.

Пример:

```text
Клиент:
http://localhost:8881/api/chat

Прокси пересылает запрос:
http://localhost:11434/api/chat
```

Прокси сохраняет доступную статистику и передаёт ответ клиенту.

Для корректного мониторинга потоковых запросов необходимо сохранять потоковую передачу данных без буферизации всего ответа.

**Для получения подробной статистики отдельных запросов рекомендуется использовать Proxy Monitoring.**

- Windows 10/11 x64 или Linux.
- Python 3.11 или новее.
- Установленная Ollama.
- Доступ к Ollama API.
- Свободный порт 8881.
- Несколько сотен мегабайт свободного места для приложения и базы данных.

### Для мониторинга NVIDIA GPU

Необходимо:

- Установить совместимый драйвер NVIDIA.
- Проверить доступность видеокарт.
- Убедиться, что NVIDIA Management Library или `nvidia-smi` доступны системе.

CUDA Toolkit не следует считать обязательным требованием для самого монитора.

Ollama должна быть установлена и настроена отдельно.

## 8. Использование API-прокси

После запуска приложения клиентские программы могут использовать адрес Ollama Monitor вместо прямого адреса Ollama.

### Пример запроса

```powershell
$body = @{
    model = "gemma4:latest"
    messages = @(
        @{
            role = "user"
            content = "Напиши функцию сортировки на Python"
        }
    )
    stream = $false
} | ConvertTo-Json -Depth 10

Invoke-RestMethod `
    -Uri "http://localhost:8881/api/chat" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

Укажите название модели, установленной в вашей Ollama.

Запрос должен пройти через монитор, а доступная статистика должна сохраниться в истории.

### Идентификация клиента

Для определения приложения можно передавать заголовок:

`X-Ollama-Monitor-Client`

Например:

```http
X-Ollama-Monitor-Client: PythonScript
```

Для группировки запросов в сессию можно использовать:

```http
X-Ollama-Monitor-Session: project-001
```

Поддержка этих заголовков должна быть реализована в соответствующей версии монитора.

Если заголовок отсутствует, система использует доступные сведения о клиенте.

## 9. Скорость генерации

Ollama возвращает статистику выполнения некоторых запросов.

К основным показателям относятся:

| Параметр | Значение |
|---|---|
| `total_duration` | Общее время выполнения |
| `load_duration` | Время загрузки модели |
| `prompt_eval_count` | Количество входных токенов |
| `prompt_eval_duration` | Время обработки входного контекста |
| `eval_count` | Количество сгенерированных токенов |
| `eval_duration` | Время генерации |

Продолжительность передаётся в наносекундах.

### Скорость генерации

Формула:

```text
generation_speed =
    eval_count / (eval_duration / 1_000_000_000)
```

Пример:

```text
eval_count = 500
eval_duration = 10_000_000_000
```

Результат:

```text
50 токенов/с
```

### Скорость обработки контекста

Формула:

```text
prompt_processing_speed =
    prompt_eval_count / (prompt_eval_duration / 1_000_000_000)
```

Эти показатели необходимо рассматривать отдельно.

Скорость генерации не показывает, насколько быстро модель обрабатывает большой входной контекст.

При отсутствии соответствующих полей статистика должна обозначаться как недоступная.

## 10. Мониторинг нескольких GPU

При использовании нескольких видеокарт система отображает каждое устройство отдельно.

Например:

```text
GPU 0: Tesla V100 16 GB
GPU 1: RTX A4000 16 GB
```

Для каждой карты показываются доступные показатели загрузки и видеопамяти.

Это позволяет оценить:

- Насколько эффективно используется каждая видеокарта.
- Растёт ли загрузка GPU во время генерации.
- Как изменяется использование VRAM.
- Возникает ли нехватка видеопамяти.
- Как влияет конфигурация GPU на работу моделей.

Монитор не должен самостоятельно изменять настройки распределения моделей между видеокартами.

Распределение вычислений выполняет Ollama и используемый ею backend.

## 11. База данных и история

SQLite используется для локального хранения статистики.

Основные категории данных:

- История запросов.
- Статистика моделей.
- Сведения о клиентах.
- Метрики GPU.
- Системные события.
- Настройки приложения.

История должна сохраняться после перезапуска.

Необходимо контролировать рост базы данных.

Для старых метрик GPU рекомендуется использовать агрегацию, чтобы уменьшить объём хранимых данных.

По умолчанию не следует сохранять полные тексты запросов и ответов: они могут содержать исходный код, конфиденциальные сведения и другие чувствительные данные.

## 12. Производительность

Ollama Monitor должен минимально влиять на работу Ollama.

Для этого необходимо:

- Использовать асинхронный HTTP-прокси.
- Переиспользовать HTTP-соединения.
- Не блокировать event loop.
- Не буферизовать потоковые ответы целиком.
- Ограничивать очереди событий.
- Не выполнять тяжёлые операции с SQLite в обработчиках запросов.
- Контролировать фоновые задачи.
- Корректно обрабатывать отключения клиентов.

Фактические накладные расходы следует измерять тестами.

## 15. Устранение неполадок

### Ollama недоступна

Проверьте:

```powershell
Invoke-RestMethod http://localhost:11434/api/version
```

Убедитесь, что сервер Ollama запущен и адрес в конфигурации указан правильно.

### Порт 8881 занят

Проверьте:

```powershell
netstat -ano | findstr :8881
```

Если порт используется другим приложением, освободите его или измените настройку порта в конфигурации.

### Не отображается GPU

Проверьте:

```powershell
nvidia-smi
```

Если команда недоступна, проверьте драйвер NVIDIA и доступность NVML.

Отсутствие GPU-мониторинга не должно мешать работе остальных функций приложения.

### Нет скорости генерации

Проверьте, проходит ли запрос через прокси и возвращает ли Ollama статистику выполнения.

Для некоторых API статистика доступна только после завершения генерации.

### Нет названия приложения

Если клиент не передаёт идентифицирующий заголовок, название может отображаться как `Unknown Client`.

IP-адрес сам по себе не позволяет надёжно определить конкретное приложение.

## 17. Ограничения

Ollama Monitor не является инструментом, который может гарантированно получить любые сведения о внутренних операциях Ollama.

Доступность показателей зависит от API, версии Ollama, драйверов и аппаратного обеспечения.

В частности:

- Пассивный мониторинг не гарантирует полной статистики каждого запроса.
- Некоторые OpenAI-совместимые ответы могут не содержать точных данных о токенах.
- Время до первого байта не равно времени до первого токена.
- Общая VRAM нескольких GPU не эквивалентна памяти одного устройства.
- Определение клиентского приложения по IP и User-Agent может быть неточным.
- Системная загрузка GPU не всегда позволяет определить, какая именно модель использует вычислительные ресурсы.
- Скорость генерации зависит от размера контекста, квантования, модели и параллельных запросов.

Все недоступные показатели должны отображаться явно, без подмены вымышленными значениями.

## 18. Принцип работы проекта

Ollama Monitor должен предоставлять единое место для наблюдения за локальными моделями и анализа их производительности.

Главная цель — получить объективную картину того, как работают модели на конкретном оборудовании и насколько эффективно они подходят для программирующих агентов.

Система должна быть локальной, расширяемой и пригодной для длительной эксплуатации.

**Основной адрес:** `http://localhost:8881`

**Основной сервер моделей:** `http://localhost:11434`
